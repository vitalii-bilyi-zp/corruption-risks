# Мікросервіс прогнозування вартості відновлення будівель

## 1. Призначення мікросервісу

### 1.1. Загальний опис

Мікросервіс являє собою інтелектуальну систему прогнозування вартості відновлення пошкоджених внаслідок бойових дій будівель на території України. Система реалізована мовою програмування Python та надає REST API для інтеграції з веб-додатками та іншими інформаційними системами.

### 1.2. Функціональні можливості

Основні функції мікросервісу:

1. **Прогнозування вартості відновлення** — обчислення орієнтовної вартості ремонтно-відновлювальних робіт на основі характеристик об'єкта
2. **Пояснення прогнозу (Explainable AI)** — декомпозиція прогнозованої вартості на внески окремих факторів із використанням методу SHAP (SHapley Additive exPlanations)
3. **Підтримка множинних моделей** — можливість використання альтернативних алгоритмів машинного навчання (XGBoost, Random Forest, Linear Regression)
4. **Інфляційне коригування вартості** — приведення базового прогнозу (ціни 2024-01) до цін планованого місяця виконання робіт. Коефіцієнти передаються Laravel-ом з БД у кожному запиті (`inflation_indices`); якщо потрібна пара (рік, місяць) відсутня у переданій таблиці — повертається `HTTP 400`

### 1.3. Предметна область

Система орієнтована на автоматизацію процесу оцінювання вартості відновлення об'єктів будівельної інфраструктури, що постраждали внаслідок воєнних дій. Вхідними даними слугують фізичні та географічні характеристики будівлі, ступінь пошкодження та необхідний тип ремонту.


### 2.4. Модуль кодування ознак (encoding.py)

Модуль `encoding.py` реалізує гібридну систему кодування категоріальних ознак із підтримкою зворотної сумісності.

#### 2.4.1. Версійність кодування

| Версія | Метод кодування | Опис |
|--------|-----------------|------|
| **v1.0** | One-Hot Encoding | Класичне бінарне кодування для всіх категоріальних ознак |
| **v2.0** | Fuzzy + One-Hot | Нечітке кодування для порядкових ознак, One-Hot для номінальних |

#### 2.4.2. Fuzzy-кодування порядкових ознак

Для порядкових (ординальних) ознак застосовується нечітке кодування на основі трикутних функцій належності:

**Функція належності:**

```
         μ(x)
          ▲
        1 │      /\
          │     /  \
          │    /    \
        0 │___/______\___
              a   b   c    → x

Трикутна функція μ(x; a, b, c):
         ⎧ 0,           x ≤ a або x ≥ c
μ(x) =   ⎨ (x-a)/(b-a), a < x ≤ b
         ⎩ (c-x)/(c-b), b < x < c
```

**Конфігурація порядкових ознак:**

| Ознака | Категорії | Числові позиції |
|--------|-----------|-----------------|
| `damage_level` | Легке → Середнє → Тяжке | 0.0 → 0.5 → 1.0 |
| `repair_type` | Поточний → Капітальний → Повна реконструкція | 0.0 → 0.5 → 1.0 |

Fuzzy-кодування зберігає градієнтну інформацію про впорядкованість категорій, на відміну від One-Hot кодування, яке втрачає цю семантику.

#### 2.4.3. One-Hot кодування номінальних ознак

Для номінальних (невпорядкованих) ознак застосовується стандартне One-Hot кодування:

- `building_type` — 5 категорій
- `region` — 22 категорії (міста та області України)

### 2.6. Модуль інфляційного коригування (inflation.py)

Модуль реалізує приведення базового прогнозу (ціни 2024-01) до цін довільного місяця виконання робіт.

#### 2.6.1. Принцип роботи

```
V_adjusted(y, m) = V_base × k(y, m)

k(y, m) = CPI(y, m) / CPI(2024, 01)
```

- `V_base` — прогноз моделі ML (ціни 2024-01)
- `k(y, m)` — коефіцієнт, що передається Laravel-ом з таблиці `inflation_indices` у кожному запиті
- `BASE_YEAR = 2024`, `BASE_MONTH = 1`

#### 2.6.2. Джерело коефіцієнтів

Коефіцієнти **не зберігаються** у коді мікросервісу. Laravel передає актуальну таблицю у полі `inflation_indices` кожного запиту. Це гарантує, що Flask завжди використовує значення з БД, а не застарілі вбудовані константи.

Якщо `work_year`/`work_month` не передані — коригування не застосовується (`k = 1.0`).  
Якщо `work_year`/`work_month` передані, але `inflation_indices` порожні або не містять потрібної пари — повертається `HTTP 400`.

#### 2.6.3. Клас `InflationService`

```python
class InflationService:
    def get_coefficient(
        self,
        work_year: Optional[int],
        work_month: Optional[int],
        indices: Optional[list] = None,
    ) -> float:
        """
        Повертає k для заданої пари (year, month).
        Якщо обидва None — повертає 1.0 (без коригування).
        Raises ValueError якщо пару не знайдено у indices.
        """

    def apply(
        self,
        base_cost: float,
        work_year: Optional[int],
        work_month: Optional[int],
        indices: Optional[list] = None,
    ) -> dict:
        """
        Повертає dict з полями:
          adjusted_cost — скоригована вартість (грн)
          inflation_k   — використаний коефіцієнт
          base_year     — базовий рік моделі (2024)
          base_month    — базовий місяць моделі (1)
          work_year     — рік виконання робіт
          work_month    — місяць виконання робіт
        Raises ValueError (→ HTTP 400) якщо коефіцієнт не знайдено.
        """
```

## 3. Опис ML моделей та алгоритмів

### 3.1. Основна модель: XGBoost Regressor

#### 3.1.1. Теоретичні засади

XGBoost (eXtreme Gradient Boosting) — це імплементація алгоритму градієнтного бустингу, оптимізована для швидкодії та ефективності. Модель будує ансамбль дерев рішень, де кожне наступне дерево коригує помилки попередніх.

**Цільова функція оптимізації:**

```
Obj(θ) = Σᵢ L(yᵢ, ŷᵢ) + Σₖ Ω(fₖ)
```

де:
- `L(yᵢ, ŷᵢ)` — функція втрат (квадратична похибка для регресії)
- `Ω(fₖ)` — регуляризаційний член для дерева `fₖ`

#### 3.1.2. Параметри моделі

```python
model = xgb.XGBRegressor(
    objective="reg:squarederror",  # Квадратична функція втрат
    random_state=1                  # Фіксація випадковості
)
```

#### 3.1.3. Процес навчання

1. Завантаження даних із CSV-файлу
2. Кодування ознак через `FeatureEncoder`
3. Розбиття на навчальну (80%) та тестову (20%) вибірки
4. Навчання моделі
5. Обчислення глобальної важливості ознак (SHAP)
6. Серіалізація моделі та метаданих

### 3.2. Альтернативні моделі

#### 3.2.1. Linear Regression

Лінійна регресія використовує порядкове (ordinal) кодування категоріальних ознак:

```python
def encode_ordinal(df, columns):
    for col in columns:
        df[col] = df[col].astype("category").cat.codes + 1
    return df
```

**Аналітичний вираз моделі:**

```
V = β₀ + β₁·area + β₂·floors + β₃·building_type + β₄·damage_level + β₅·region + β₆·repair_type
```

де `βᵢ` — коефіцієнти моделі.

#### 3.2.2. Random Forest Regressor

```python
model = RandomForestRegressor(
    random_state=42,
    n_estimators=100  # Кількість дерев в ансамблі
)
```

Random Forest використовує One-Hot кодування та будує ансамбль незалежних дерев рішень з агрегацією прогнозів через усереднення.

### 3.3. Інтерпретованість моделей (SHAP)

#### 3.3.1. Теоретичні засади SHAP

SHAP (SHapley Additive exPlanations) базується на значеннях Шеплі з теорії ігор для пояснення внеску кожної ознаки у прогноз:

```
ŷ = φ₀ + Σⱼ φⱼ
```

де:
- `φ₀` — базове значення (середнє прогнозу по навчальній вибірці)
- `φⱼ` — внесок j-ої ознаки у прогноз

#### 3.3.2. Агрегація SHAP-значень

Для агрегації локальних SHAP-значень по групах ознак:

```python
def aggregate_local_contrib(shap_vec, feature_columns, feature_groups):
    """
    Агрегує SHAP-значення за групами оригінальних ознак.

    Returns:
        ordered: відсортований список (група, внесок)
        per_group_pct: відсоткова важливість кожної групи
    """
    per_feature = {feat: val for feat, val in zip(feature_columns, shap_vec)}
    per_group = {}
    for g, cols in feature_groups.items():
        per_group[g] = sum(per_feature.get(c, 0.0) for c in cols)

    denom = sum(abs(v) for v in per_group.values()) or 1.0
    per_group_pct = {g: (abs(v) / denom) * 100.0 for g, v in per_group.items()}

    return sorted(per_group.items(), key=lambda kv: abs(kv[1]), reverse=True), per_group_pct
```

#### 3.3.3. Резервний механізм

У разі недоступності SHAP використовується важливість ознак на основі приросту (gain) з XGBoost:

```python
booster = model.get_booster()
gain = booster.get_score(importance_type="gain")
```

### 3.4. Порівняння методів кодування

Скрипт `compare_encodings.py` реалізує A/B-тестування One-Hot та Fuzzy кодування:

**Методологія:**
- K-Fold крос-валідація (k=5)
- Метрики: MAE, RMSE, R², MAPE
- Парний t-тест для статистичної значущості

**Тест монотонності:**
Перевірка, що прогнози зростають із збільшенням рівня пошкодження:
```
damage_level: Легке → Середнє → Тяжке
cost:         ↑        ↑         ↑
```

### 4.3. Схема вхідних даних

```python
class InflationIndexRow(BaseModel):
    year:        int
    month:       int
    index_value: float


class Payload(BaseModel):
    area:          float = Field(..., ge=0)
    floors:        int   = Field(..., ge=0)
    building_type: str
    damage_level:  str
    region:        str
    repair_type:   str
    work_year:  Optional[int] = Field(default=None, ge=2020, le=2040)
    work_month: Optional[int] = Field(default=None, ge=1, le=12)
    inflation_indices: Optional[List[InflationIndexRow]] = None

    @model_validator(mode='after')
    def check_year_month_together(self):
        year_given  = self.work_year  is not None
        month_given = self.work_month is not None
        if year_given != month_given:
            raise ValueError(
                'work_year та work_month мають передаватись разом або не передаватись взагалі'
            )
        return self
```

> **Важливо:** `work_year`, `work_month` та `inflation_indices` виключаються з вхідних даних моделі ML і використовуються виключно для інфляційного коригування після отримання прогнозу. `work_year`/`work_month` приймаються лише в парі — передача одного без іншого повертає `400`. `inflation_indices` обов'язкова якщо задано `work_year`/`work_month` — відсутність або відсутність потрібної пари повертає `400`.

Усі ендпоінти, крім `/health`, захищені автентифікацією через API-ключ:

```python
def check_key(req) -> bool:
    """Перевірка API-ключа для автентифікації."""
    return bool(API_KEY) and req.headers.get("X-API-Key") == API_KEY
```

## 10. Висновки

Розроблений мікросервіс реалізує повний цикл прогнозування вартості відновлення пошкоджених будівель:

1. **Гнучка система кодування ознак** із підтримкою Fuzzy-логіки для порядкових категорій
2. **Множинні алгоритми ML** з можливістю вибору оптимального
3. **Інтерпретованість прогнозів** через SHAP-аналіз
4. **REST API** для інтеграції з веб-додатками
5. **Зворотна сумісність** між версіями кодування
6. **Щомісячне інфляційне коригування** — приведення прогнозу до цін конкретного місяця виконання робіт; коефіцієнти керуються з БД Laravel і передаються у кожному запиті

Мікросервіс може бути розгорнутий як автономний контейнер або інтегрований у більшу архітектуру мікросервісів.
